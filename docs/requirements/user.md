# User Requirements

## 목적

OAuth 로그인 이후 서비스 이용에 필요한 사용자 정보, 프로필, 학교 인증 정보, 탈퇴/복구 동작을 정의한다.

## 기능 요구사항

- OAuth 로그인으로 생성된 사용자는 서비스 이용에 필요한 추가 정보를 입력해 회원가입을 완료할 수 있어야 한다.
- 회원가입 완료 시 사용자의 권한은 일반 사용자 권한으로 변경되어야 한다.
- 회원가입 완료 후 사용자는 인증 토큰을 다시 발급받아야 한다.
- 사용자는 자신의 프로필 정보를 조회할 수 있어야 한다.
- 사용자는 프로필 이미지와 닉네임을 수정할 수 있어야 한다.
- 사용자는 닉네임 사용 가능 여부를 확인할 수 있어야 한다.
- 사용자는 학교 이메일 인증 절차를 수행할 수 있어야 한다.
- 사용자는 탈퇴할 수 있어야 한다.
- 탈퇴한 사용자는 정해진 복구 절차를 통해 계정을 복구할 수 있어야 한다.

## 비기능 요구사항

- 사용자 식별 정보와 학교 인증 정보는 중복 없이 일관되게 유지되어야 한다.
- 프로필 수정, 탈퇴, 복구 같은 사용자 상태 변경은 트랜잭션으로 처리되어야 한다.
- 개인정보 조회/수정 API는 인증된 본인 요청만 허용해야 한다.
- 탈퇴 처리 후에도 고유 제약 조건 때문에 재가입 또는 복구가 막히지 않아야 한다.
- 이메일 인증 코드는 제한된 시간 동안만 유효해야 하며 재사용을 방지해야 한다.

## 예외/제약사항

- 학교 이메일은 중복될 수 없다.
- 학번은 중복될 수 없다.
- 닉네임은 중복될 수 없다.
- 탈퇴 시 사용자 식별 정보는 재가입/복구 정책에 맞게 충돌이 나지 않도록 처리되어야 한다.
- 로그인/토큰 세션 관련 요구사항은 [auth.md](auth.md)를 따른다.

## 관련 API

- `POST /api/v1/user/complete-registration`: 회원가입 완료
- `GET /api/v1/user/profile`: 프로필 조회
- `POST /api/v1/user/profile`: 프로필 수정
- `GET /api/v1/user/nickname/verify`: 닉네임 중복 확인
- `POST /api/v1/email/request-code`: 학교 이메일 인증 코드 요청
- `POST /api/v1/email/verify-code`: 학교 이메일 인증 코드 검증
- `DELETE /api/v1/user/logout`: 로그아웃
- `DELETE /api/v1/user/withdraw`: 회원 탈퇴
- `POST /api/v1/user/restore`: 회원 복구

## 검증 시나리오

- 신규 OAuth 사용자가 필수 정보를 입력하면 회원가입이 완료되고 토큰을 받는다.
- 이미 사용 중인 학교 이메일이나 학번으로 회원가입 완료를 요청하면 실패한다.
- 이미 사용 중인 닉네임은 사용할 수 없다는 결과를 반환한다.
- 사용자는 자신의 프로필만 조회/수정할 수 있다.
- 탈퇴한 사용자는 복구 API를 통해 계정을 복구할 수 있다.
