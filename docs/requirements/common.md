# Common Requirements

## 목적

모든 기능에 공통으로 적용되는 응답 형식, 예외 처리, 권한, 시간 기준을 정의한다.

## 기능 요구사항

- 모든 API는 성공/실패 응답 형식을 일관되게 제공해야 한다.
- 실패 응답은 클라이언트가 원인을 구분할 수 있는 에러 코드를 포함해야 한다.
- 인증이 필요한 API는 유효한 Access Token을 요구해야 한다.
- 사용자 권한이 필요한 API는 일반 사용자 권한을 확인해야 한다.
- 관리자 권한이 필요한 API는 관리자 권한을 확인해야 한다.
- 사용자 식별이 필요한 API는 인증 토큰의 사용자 정보를 기준으로 처리해야 한다.
- 서버가 기록하는 시간은 서버 시간을 기준으로 해야 한다.

## 비기능 요구사항

- API 응답 형식과 에러 코드 체계는 모든 도메인에서 일관되어야 한다.
- 인증/인가 실패는 보안상 필요한 최소 정보만 노출해야 한다.
- 서버 시간 기준은 배포 환경 간 차이가 발생하지 않도록 관리되어야 한다.
- 외부 서비스, DB, Redis 장애는 로그와 모니터링으로 추적 가능해야 한다.
- 반복되는 스케줄러 작업은 실패해도 다음 실행에서 복구 가능해야 한다.
- 민감 설정 정보는 코드 저장소에 직접 노출되지 않도록 관리되어야 한다.

## 예외/제약사항

- 클라이언트가 전달한 사용자 ID를 신뢰해 권한을 판단해서는 안 된다.
- 인증 실패, 권한 부족, 리소스 없음, 입력값 오류는 구분 가능한 응답으로 처리되어야 한다.
- 외부 서비스 연동 실패는 핵심 데이터 정합성을 해치지 않도록 처리되어야 한다.

## 검증 시나리오

- 인증이 필요한 API를 토큰 없이 호출하면 실패한다.
- 일반 사용자가 관리자 API를 호출하면 실패한다.
- 존재하지 않는 리소스를 조회하면 일관된 실패 응답을 받는다.
- 입력값 검증 실패 시 클라이언트가 원인을 확인할 수 있는 응답을 받는다.
