# Badge Requirements

## 목적

사용자의 서비스 활동에 따라 배지를 부여하고, 사용자가 보유 배지와 대표 배지를 관리할 수 있도록 한다.

## 기능 요구사항

- 사용자는 자신이 획득한 배지 목록을 조회할 수 있어야 한다.
- 사용자는 전체 배지 목록과 획득 여부를 조회할 수 있어야 한다.
- 사용자는 대표 배지를 설정할 수 있어야 한다.
- 사용자는 아직 알림 처리되지 않은 신규 배지를 조회할 수 있어야 한다.
- 시스템은 정해진 조건을 만족한 사용자에게 배지를 부여할 수 있어야 한다.
- 같은 배지는 한 사용자에게 중복 부여되지 않아야 한다.
- 신규 회원에게 웰컴 배지를 부여할 수 있어야 한다.

## 비기능 요구사항

- 배지 부여는 중복 요청이나 재시도 상황에서도 같은 배지가 중복 저장되지 않아야 한다.
- 배지 획득 조건은 추적 가능하고 테스트 가능한 형태로 관리되어야 한다.
- 대표 배지 변경은 사용자 프로필 조회와 일관된 결과를 제공해야 한다.
- 미알림 배지 조회는 사용자가 이미 확인한 배지를 반복 노출하지 않아야 한다.

## 예외/제약사항

- 존재하지 않는 배지는 대표 배지로 설정할 수 없다.
- 사용자가 보유하지 않은 배지는 대표 배지로 설정할 수 없다.
- 배지 코드는 중복될 수 없다.

## 관련 API

- `POST /api/v1/badge`: 배지 생성
- `GET /api/v1/badge`: 전체 배지 목록 조회
- `DELETE /api/v1/badge/{badgeId}`: 배지 삭제
- `GET /api/v1/badge/me`: 내 배지 목록 조회
- `POST /api/v1/badge/me/representative-badge`: 대표 배지 설정
- `GET /api/v1/badge/unnotified`: 미알림 신규 배지 조회

## 검증 시나리오

- 신규 회원가입 완료 시 웰컴 배지가 부여된다.
- 사용자는 획득한 배지와 미획득 배지를 구분해 조회할 수 있다.
- 사용자는 보유한 배지를 대표 배지로 설정할 수 있다.
- 같은 배지를 중복으로 획득하지 않는다.
