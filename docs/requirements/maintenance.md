# Maintenance Requirements

## 목적

서비스 점검 상태를 관리하고, 점검 중 사용자 요청 처리 정책을 정의한다.

## 기능 요구사항

- 관리자는 점검 모드를 활성화할 수 있어야 한다.
- 관리자는 점검 모드를 비활성화할 수 있어야 한다.
- 사용자는 현재 점검 상태를 확인할 수 있어야 한다.
- 점검 모드가 활성화된 경우 일반 사용자 API 요청은 점검 응답을 받을 수 있어야 한다.
- 점검 모드에서도 허용되어야 하는 API는 명확히 예외 처리되어야 한다.

## 비기능 요구사항

- 점검 모드 상태 변경은 관리자 권한으로만 수행되어야 한다.
- 점검 상태는 서버 재시작 후에도 의도한 상태를 유지할 수 있어야 한다.
- 점검 응답은 클라이언트가 일반 오류와 구분할 수 있는 일관된 형식을 가져야 한다.
- 점검 모드 필터는 허용된 관리/상태 확인 API를 제외하고 일관되게 적용되어야 한다.

## 예외/제약사항

- 점검 모드 변경은 관리자 권한 사용자만 수행할 수 있어야 한다.
- 점검 응답은 클라이언트가 점검 상태임을 구분할 수 있는 일관된 형식이어야 한다.
- 관리자용 점검 제어 API는 점검 모드에 의해 차단되지 않아야 한다.

## 관련 API

- `GET /api/v1/maintenance/status`: 점검 상태 조회
- `PATCH /api/v1/maintenance/status`: 점검 모드 변경

## 검증 시나리오

- 관리자가 점검 모드를 켜면 일반 사용자 요청은 점검 응답을 받는다.
- 관리자가 점검 모드를 끄면 일반 사용자 요청이 정상 처리된다.
- 일반 사용자는 점검 모드를 변경할 수 없다.
